# Playbooks — Project

**How a project is run here**: the team's shared practice, not step-by-step checklists. Load the relevant playbook before doing that kind of work, so a project runs the same way no matter who, or which agent, is running it.

A playbook is *philosophy plus approach*; the mechanical "do X then Y" belongs in a [process](../processes/README.md). A playbook earns its place once there is a real point of view on the domain. Add one when you notice you keep re-explaining "how we approach X". Name it for its domain.

## Playbooks

| Playbook | Load it when |
|---|---|
| [`ways-of-working.md`](ways-of-working.md) | You need to know how the team runs a project: its meetings, its channels, when people are available, who decides and what done means |
| [`joining-a-project.md`](joining-a-project.md) | Someone joins a project, or you are helping them get going |

Both open with a **Not filled in yet** box until the team has said how it works. Copy [`_template.md`](_template.md) when the next one is written, and list it here.
