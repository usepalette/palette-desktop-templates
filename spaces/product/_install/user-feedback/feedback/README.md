# Feedback

Short product signals captured close to their source: chat messages, email replies, support notes, comments on calls and reactions someone saw.

Say "capture this feedback" ([`../../processes/capture-feedback.md`](../../processes/capture-feedback.md)), or copy [`../_template.md`](../_template.md) here as `YYYY-MM-DD_company_person_topic.md`.

## Rules

- Keep the meaning of what was said. Use the exact words when you have them.
- Record `source_url` whenever there is a link, a ticket, a recording or an email reference. Write `unavailable` rather than inventing one.
- Set `capture_mode` to `verbatim`, `paraphrase` or `summary`.
- Exact quotes go under `## Their words`. Leave that section out when the source's wording isn't available.
- A single complaint stays here, unless it is an explicit feature request or a clearly blocking problem from a structured interview.
- When someone asks for a specific capability, create or update a linked file in [`../feature-requests/`](../feature-requests/README.md).
- Never make a recurring painpoint from one casual comment.
- Rebuild the dashboard after adding or changing an entry: [`../../processes/rebuild-feedback-dashboard.md`](../../processes/rebuild-feedback-dashboard.md).
