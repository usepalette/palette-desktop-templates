# Specs

Short briefs for one buildable piece of work, each linked to the evidence behind it.

This space keeps the draft and its evidence. The tracker named in [`company/tools.md`](../../../company/tools.md), when the team uses one, owns who builds it, its status, its delivery and the roadmap.

## Rules

- Say "write this up for engineering" ([`../processes/write-a-spec.md`](../processes/write-a-spec.md)), or copy [`_template.md`](_template.md).
- Name the file for what ships, in kebab-case.
- Link the painpoint, the discovery result, the strategy thesis or the other evidence that justifies the work.
- Keep it tight. When a section turns into a research essay, move that material upstream, to discovery or strategy.
- When the spec is in the tracker, put the item's link in `tracker`.
- Before a spec is shared, review it: [`../processes/review-product-work.md`](../processes/review-product-work.md).
