# Principles

How we think about a design: how a screen is composed, layered, structured, written and named. Read the page for what you are doing before designing or building, and cite the principle when a decision matters. These are defaults. Break one on purpose, and know what you are breaking and why.

> **Not confirmed yet.** Every page here is a starter set. Read them as a team, change what you disagree with, delete what does not apply, add your own, and delete this box when the folder says what you believe. Delete the box on a page when that page is done.

The specific calls that come out of real work are in [`../rules/`](../rules/README.md). How the work is done is in [`../process/`](../process/README.md). The tokens and components are the design system's, in [`../design-system/`](../design-system/README.md).

When designing inside an existing product, the patterns already there are the binding constraint: [`philosophy.md`](philosophy.md) → "What ships is the strongest reference".

## Changing a principle

A principle changes when the team agrees, and the change gets a line in the root `log.md`. A rule that has become a way of thinking moves here from [`../rules/`](../rules/README.md) and is deleted there.
