# Glossary

> **Mold.** The format of a project's glossary; don't fill it in here. Copy it into a project as `projects/<name>/glossary.md` when the project has words of its own: the customer's terms, the names of the parts of the work, its abbreviations.
>
> In the copy: everything from **Fill in** down, with its own full frontmatter as `type: doc` ([`README.md`](README.md) → How templates work), and a row for it in the Links table of the project's `README.md`. Write only what you were given, and replace the bracketed row with the real words.

The project's own words, the ones a newcomer or an agent would trip on in its meetings and pages. One row each, in alphabetical order.

## How to write this

- **Load first:** [`company/glossary.md`](../../../company/glossary.md). A word the whole company uses belongs there, not here; this page holds only the project's own.
- **Add a word when it first trips someone up.** A glossary filled in as the project goes is better than none.
- **Quality bar:** someone new reads a meeting note on the project without having to ask what a word means.
