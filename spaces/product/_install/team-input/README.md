# Team input

What the people involved in the product are pushing for now: their priorities, their constraints and the evidence they point to. They may be the person who set up the space, their teammates or colleagues from other teams.

This is input to product decisions, not the roadmap. Initiatives, projects, tasks, status and dates stay in the tracker named in [`company/tools.md`](../../../company/tools.md), when the team uses one.

## A person's input

One file per person, `<name>.md`, named like their folder in the root [`people/`](../../../people/README.md) and updated in place. Copy [`_person-template.md`](_person-template.md). How to work with someone is in their profile there; what they want from the product now is here, and the file links to the profile.

## Roadmap syncs

A roadmap or planning conversation is a meeting: say "log this meeting". Its note goes where [`company/meetings.md`](../../../company/meetings.md) puts a meeting about a space's work, in this space's meetings folder, named `YYYY-MM-DD-roadmap-sync.md`. Write it from [`_roadmap-sync-template.md`](_roadmap-sync-template.md): the framing, the evidence reviewed, the decisions, the changes in the tracker and the open questions.

Then update the input of each person whose priorities moved, and add each real decision to this space's [`log.md`](../log.md).
