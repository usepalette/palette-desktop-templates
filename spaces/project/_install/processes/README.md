# Processes — Project

**How things are done here**: step-by-step, specific, actionable. A process can stand alone or be referenced by a [playbook](../playbooks/README.md). The playbook says *why and how to think*; the process says *what to do, in which order*.

A process written this way can be handed to an agent as it stands: name the process, and the steps are followed in order. That is the progression: first a person reads it, then an agent runs it.

## Processes

| Process | Run it when |
|---|---|
| [`start-a-project.md`](start-a-project.md) | Someone says "we're starting a new project": the workspace's steps for a project, then the extras this team uses |
| [`record-a-decision.md`](record-a-decision.md) | Something is decided on a project: "we decided …", "record this decision", or the scope changed |

Meetings and closing a project follow the workspace's own steps. Say "log this meeting" ([`company/meetings.md`](../../../company/meetings.md)) or "that project is done" ([`projects/README.md`](../../../projects/README.md) → Close a project).
