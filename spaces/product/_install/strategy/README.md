# Strategy

Durable claims about how the product wins: its positioning, its moat or its sequencing. Not a list of what ships next.

## What belongs here

A thesis outlives one planning window. It connects the evidence from user feedback, discovery, competitors, analytics and team input to a claim about how the product wins.

Specific builds belong in [`../specs/`](../specs/README.md) and in the tracker named in [`company/tools.md`](../../../company/tools.md). Open questions belong in [`../discovery/`](../discovery/README.md). What competitors ship is in [`company/market/competitors/`](../../../company/market/competitors/README.md).

## How to work

- Copy [`_template.md`](_template.md). Name the file for the thesis, not for the meeting where it came up.
- Include the counter-arguments. A thesis without a credible counter is advocacy, not strategy.
- Link the evidence it stands on, and what it changes downstream.
- When the thesis changes materially, add a revision note instead of rewriting its history away.
- `status` is `draft` while the thesis is argued, `active` once the team holds it, `parked` when it is set aside, and `archived` when it no longer holds.
