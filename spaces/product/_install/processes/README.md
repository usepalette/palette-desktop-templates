# Processes — Product

**How things are done here**: step-by-step, specific, actionable. A process can stand alone or be referenced by a [playbook](../playbooks/README.md). The playbook says *why and how to think*; the process says *what to do, in which order*.

A process written this way can be handed to an agent as it stands: name the process, and the steps are followed in order. Nobody has to name it, though: people say what they want in their own words, and the agent follows the matching page.

## Processes

| Process | Run it when | Say |
|---|---|---|
| [`capture-feedback.md`](capture-feedback.md) | A user said something about the product, an interview happened, or someone asked for a capability | "A customer just told me…", "capture this feedback" |
| [`synthesise-feedback.md`](synthesise-feedback.md) | The same problem keeps coming up, or a slice of feedback needs sorting into painpoints and requests | "We keep hearing this", "what are customers saying about [a topic]?" |
| [`rebuild-feedback-dashboard.md`](rebuild-feedback-dashboard.md) | Feedback, an interview, a request or a painpoint was added or changed | "Rebuild the feedback dashboard" |
| [`share-feedback.md`](share-feedback.md) | Someone needs a sourced recap for a team, a customer or a stakeholder | "Recap the feedback on [a company or a topic]" |
| [`write-a-spec.md`](write-a-spec.md) | A piece of work is ready to be written up for the people who build it | "Write this up for engineering", "draft a spec for [the work]" |
| [`review-product-work.md`](review-product-work.md) | A spec or a strategy thesis is about to be shared, or someone asks for a check | "Review this spec", "check the evidence behind this" |

Copy [`_template.md`](_template.md) to add one, and list it here. These pages are a first version: change them when the team works differently, and log the change in the space's `log.md`.
